# 2교시 · API 문서 분석과 요청 구문 설계

10:30~11:30. 언어모델을 처음 도구로 씁니다. 대화 상대가 아니라 **문서 파서**로 씁니다.

**Claude Code가 없어도 이 교시를 전부 따라올 수 있습니다.** 각 프롬프트 아래 `관전 트랙` 상자에 터미널만으로 같은 것을 확인하는 방법과, claude.ai 무료 웹에서 해볼 수 있는 프롬프트가 함께 있습니다.

## 1. 명세서 양식 (10:30)

수집 코드를 짜는 데 반드시 필요한 8항목입니다. 이 양식을 고정하는 것 자체가 실패 방지 장치입니다.

```
endpoint · params_required · params_optional · auth · response_shape · data_path · error_codes · pagination · rate_limit
```

등록 양식 전체는 `references/api-registry.md` 맨 아래에 있습니다.

> **관전 트랙** — 에이전트 없이 같은 것을 확인합니다.
>
> ```bash
> python exercises/02/offline_tour.py
> ```
>
> 완성된 명세서 8요소를 보여주고, 그 명세서를 **스냅샷 응답으로 검증**합니다. 호출도 인증키도 없이 2교시 전체를 따라갈 수 있습니다.

## 2. MCP로 표 찾기 (10:42)

`mcp-kosis.md`를 따릅니다. KOSIS MCP 서버가 연결된 분만 직접, 나머지는 강사 화면으로.

> **관전 트랙** — 에이전트 없이 같은 것을 확인합니다.
>
> MCP 없이도 KOSIS 통계표는 찾을 수 있습니다. 브라우저에서 `https://kosis.kr` 통계표 화면을 열고 **Open API 버튼으로 요청 주소를 생성**하면 `tblId` · `itmId` · `objL1` 이 박힌 URL이 나옵니다. MCP 도구가 해주는 일과 결과가 같습니다.
>
> 실제로 이 저장소도 그렇게 고쳤습니다. `DT_1B81A17` 은 **시군구** 표라 시도 파이프라인에서 `err=21` 이 났고, 시도 표인 `DT_1B81A21` · `itmId=T1` 로 바로잡았습니다. `references/api-registry.md` 에 기록돼 있습니다.

## 3. 문서 → 명세서 (11:00)

> `exercises/02/worldbank-doc.md`와 `kosis-doc.md`를 읽고 `references/api-registry.md`의 등록 양식대로 명세서를 각각 작성해. 문서에 없는 항목은 '문서에 없음'으로 두고 추측하지 마. 결과는 JSON으로 `exercises/02/spec_worldbank.json`, `spec_kosis.json`에 저장해.

프롬프트에서 눈여겨볼 세 줄:
- "양식대로" → 출력 모양 고정. 다음 단계 코드가 같은 키를 기대합니다
- "문서에 없으면 '문서에 없음'" → 지어내기 차단. 이 줄이 없으면 그럴듯한 파라미터를 만들어 냅니다
- "JSON으로 저장" → 사람이 아니라 코드가 읽기 때문입니다

> **관전 트랙** — 에이전트 없이 같은 것을 확인합니다.
>
> **claude.ai 무료 웹에서 가장 잘 되는 실습입니다.** 문서를 읽고 양식대로 정리하는 일이라 파일 시스템도 실행도 필요 없습니다.
>
> `exercises/02/worldbank-doc.md` 내용을 붙여넣고:
> *다음 API 문서를 읽고 endpoint · params_required · params_optional · auth · response_shape · data_path · error_codes · pagination · rate_limit 9개 항목으로 정리해줘. 문서에 없는 항목은 '문서에 없음'으로 두고 추측하지 마. 설명 없이 JSON만 출력해.*
>
> 그 다음 **세 줄 중 하나를 빼고 다시** 시켜보세요. "추측하지 마"를 빼면 없는 파라미터가 생겨납니다. 그게 이 교시의 핵심입니다.

## 4. 명세서는 주장입니다. 검증합니다

> `spec_worldbank.json`이 맞는지 실제 호출 한 건으로 검증하는 스크립트를 만들고 실행해. HTTP 200과 JSON 파싱, 응답 최상위 구조, data_path로 관측치 도달, 필수 키 존재, 페이지 여유를 각각 확인하고 결과를 표로 보여줘. 검증 시각과 결과를 명세서 파일에 verified_at, verified_result로 추가해.

**불일치가 나오면 명세서를 고칩니다. 코드를 고치는 게 아닙니다.** 문서와 응답이 다르면 응답이 맞습니다.

> **관전 트랙** — 에이전트 없이 같은 것을 확인합니다.
>
> `offline_tour.py` 2번이 네 가지 검사를 스냅샷으로 돌립니다. 최상위 구조 · `data_path` 도달 · 필수 키 · 페이지 여유.
>
> **claude.ai 무료 웹** — 앞에서 만든 명세서 JSON 과 `raw/sample/wb_tfr.json` 앞부분을 함께 붙여넣고:
> *이 명세서가 이 응답과 맞는지 항목별로 대조해줘. 틀린 항목이 있으면 명세서 쪽을 어떻게 고쳐야 하는지 알려줘.*

KOSIS 명세서는 인증키가 있는 분만 검증까지. 없는 분은 요청 주소 조립까지만.

> 검증이 끝난 명세서를 `references/api-registry.md`의 해당 항목에 반영하고 최종 확인일자를 갱신해.
