## 소스 1 · API (13:25)

### 수집 코드 생성

프롬프트는 한 가지만 씁니다. 실패를 먼저 나열시키는 한 줄이 핵심입니다.

> `references/api-registry.md`의 World Bank 명세서로 수집 코드를 `exercises/03/collect_wb.py`에 짜줘. 먼저 이 호출에서 일어날 수 있는 실패 다섯 가지를 나열하고, 그걸 각각 처리해. 출력은 `references/schema.md`의 표준 스키마로.

### 장애 주입

`fake_api.py`는 7가지 장애(타임아웃 · 호출제한 · 0건 · 부분 페이지 · 키 변경 · 비JSON 응답)를 주입하는 가짜 응답기입니다.

> `exercises/03/fake_api.py`의 7가지 시나리오에 방금 만든 코드를 돌려서 결과를 표로 보여줘. 행 수만 보지 말고 지역 정보가 소실됐는지도 확인해.

> **관전 트랙** — 에이전트 없이 같은 것을 확인합니다.
>
> ```bash
> python exercises/03/reference/run_scenarios.py
> ```
>
> 나이브 코드와 견고한 코드를 7개 장애에 나란히 돌려 표로 보여줍니다. **`empty` · `paged` · `drift` 세 줄**을 보세요. 나이브 쪽은 각각 11행 유실 · 7행 유실 · 지역 전부 소실인데 **에러가 없습니다.** 견고한 쪽은 멈추거나 정상입니다. 조용한 실패 3 → 0.
>
> **claude.ai 무료 웹** — `exercises/03/samples/response.json` 을 붙여넣고:
> *이 API 를 매달 자동 수집한다고 할 때 일어날 수 있는 실패를 다섯 가지 나열하고, 각각 어떻게 감지할 수 있는지 알려줘.*

`empty`와 `paged`에서 **멈추는지** 확인합니다. 중단은 좋은 결과입니다. 제일 위험한 건 숫자가 나오는데 틀린 경우입니다.

참고본 `reference/run_scenarios.py`를 돌리면 나이브 코드와 견고한 코드의 차이가 표로 나옵니다.

### 세 형식 → 표준 스키마

`samples/`에 같은 지표가 JSON · XML · CSV로 있습니다. 결측 표기가 형식마다 다릅니다.

> `references/schema.md`를 읽고 표준 스키마를 강제하는 데이터클래스를 만들어. value가 비어 있으면 missing_reason이 반드시 있어야 하고, 없으면 생성 자체가 실패해야 해.

> `exercises/03/samples/`의 JSON · XML · CSV 응답을 전부 그 데이터클래스로 변환해서 하나의 데이터프레임으로 합쳐. 형식마다 결측 표기가 다른데(null / 빈 태그 / '-' / 공란) 전부 사유 코드로 옮겨. CSV의 '-'와 공란은 뜻이 다를 수 있으니 어느 코드로 갈지 나한테 물어봐.

> **관전 트랙** — 에이전트 없이 같은 것을 확인합니다.
>
> ```bash
> python exercises/03/offline_tour.py
> ```
>
> 세 형식을 전부 표준 스키마로 옮겨 27행으로 합칩니다. 결측 6건이 사유 코드별로 정리되고, **사유 없이 결측을 만들려 하면 생성 자체가 실패하는 것**까지 보여줍니다.
>
> XML 항목을 특히 보세요. `<value></value>` 와 `<value/>` 가 파서에서 **똑같이 `text=None`** 입니다. 건너뛰도록 짜면 9행이 7행이 되는데 에러가 안 납니다.
>
> **claude.ai 무료 웹** — 세 파일 내용을 함께 붙여넣고:
> *같은 지표가 세 형식으로 있어. 결측이 형식마다 어떻게 다르게 표기되는지 찾아내고, 각각을 미조사 · 해당없음 · 비공개 중 무엇으로 봐야 할지 판단이 필요한 건은 나한테 물어봐.*

XML의 빈 태그에서 값이 조용히 사라지기 쉽습니다.

## 소스 2 · 웹크롤링 (14:10)

크롤링 자체는 선수역량이라 건너뜁니다. 배우는 건 **분업**과 **조용한 실패**입니다. 실제 사이트 대신 `policy_page.html`(정책브리핑 구조를 본뜬 픽스처)을 씁니다.

> `exercises/03/policy_page.html`에서 지역별 출산지원정책 목록을 추출해. 먼저 어느 태그와 클래스에 무엇이 있는지 셀렉터를 찾아서 보여주고, 크롤링은 코드로 해. 실행 전에 같은 폴더의 robots.txt를 확인하는 루틴도 넣어.

에이전트가 셀렉터를 찾고, 코드가 긁습니다. 67건, 17개 시도가 나옵니다.

> 같은 코드를 `policy_page_v2.html`에 돌려봐.

> **관전 트랙** — 에이전트 없이 같은 것을 확인합니다.
>
> ```bash
> python exercises/03/reference/crawl_policy.py exercises/03/policy_page.html
> python exercises/03/reference/crawl_policy.py exercises/03/policy_page_v2.html
> ```
>
> 첫 줄은 **67건 · 지역 17개 · 정상**. 둘째 줄은 **0건**이고 가드가 없었다면 조용히 넘어갑니다. 지금은 `수집 0건 < 기대 최소 15건` 으로 멈춥니다.
>
> 두 HTML 을 에디터로 열어 나란히 비교해 보세요. 어느 태그와 클래스가 바뀌었는지 눈으로 찾는 것이 **에이전트가 하는 셀렉터 탐색**입니다.
>
> **claude.ai 무료 웹** — 두 파일의 목록 부분을 함께 붙여넣고:
> *두 HTML 에서 지역별 정책 목록을 뽑는 CSS 셀렉터를 각각 찾아줘. 구조가 어떻게 달라졌는지도 알려줘.*

**0건이 나오는데 에러는 없습니다.** API는 HTTP 코드가 소리를 내지만 크롤링은 그냥 조용합니다.

> 페이지 구조가 바뀌면 조용히 빈 결과를 내지 말고 멈추도록 고쳐. 기대 최소 행 수와 필수 필드를 검사에 넣어.

참고본 `reference/crawl_policy.py`. 재현성은 스냅샷이 전부입니다. 페이지는 내일 다를 수 있습니다.

## 소스 3 · 내부 연구데이터 (14:35)

`internal_panel.xlsx`는 기관 내부 자료를 가정한 엑셀입니다. 병합셀, 2단 헤더, 단위 혼재(명과 천명), `-`와 공란, 하단 각주. 실제 현장의 표 그대로입니다.

### 1단계: 해석 제안, 아직 변환하지 않음

> `exercises/03/internal_panel.xlsx`의 구조를 분석해서 어느 셀이 무엇인지 설명해. 헤더가 몇 단인지, 병합된 셀은 어디인지, 단위가 섞인 열이 있는지, 각주는 어디까지인지. 아직 변환하지 마.

> **관전 트랙** — 에이전트 없이 같은 것을 확인합니다.
>
> 엑셀로 `internal_panel.xlsx` 를 직접 열어 다섯 군데를 눈으로 찾아보세요. **병합셀 · 2단 헤더 · 단위 혼재 · `-`와 공란 · 하단 각주.** 어디서 셀이 밀릴지 짚어보는 것이 실습입니다.
>
> **claude.ai 무료 웹** — 엑셀 화면을 **캡처해서 이미지로 붙여넣고** 물어보세요. 표 구조 해석은 이미지로도 잘 됩니다.
> *이 표의 구조를 분석해줘. 헤더가 몇 단인지, 병합된 셀은 어디인지, 단위가 섞인 열이 있는지, 각주는 어디부터인지. 아직 변환하지 말고 구조만 설명해.*
>
> ⚠ **실제 기관 내부 자료로는 하지 마십시오.** 오늘 파일은 가공 샘플이라 괜찮습니다.

여기서 멈추고 **사람이 확인**합니다. "이 값이 정말 그 값인가"는 에이전트가 판단할 수 없습니다.

### 2단계: 확인한 해석대로 변환

> 확인한 해석대로 표준 스키마로 변환해. 출생아수는 명으로 통일하고(천 단위 표기는 환산), `-`는 NA_CONFIDENTIAL, 공란은 NA_NOTSURVEYED로. 2025년은 vintage 잠정. 지역명이 `references/region-codes.csv`에 없으면 멈추고 알려줘. 각주 행은 데이터로 읽지 마.

### 반출 경고

에이전트가 파일을 읽으면 그 내용이 외부 모델로 갑니다. 이 실습은 가공 샘플이라 괜찮습니다. **실제 내부 자료는 기관 규정과 데이터 등급을 확인하기 전에 절대 읽히지 않습니다.** 대안: 망분리 환경 · 사내 승인 모델 · 비식별 처리 후 사용. `CLAUDE.md`에 이 원칙이 들어 있어 에이전트가 `exercises/` 밖 파일을 읽기 전에 묻게 되어 있습니다.
